# STBOX regression run — 9 Sep 2026

Headless batch of every image in `games-share` through the sandbox ST core (Musashi + stbox.c), 60 guest-seconds each, 4 MB, keypresses/fire every 3 s after boot. The whole collection runs in ~75 s of host time per variant.

**Verdicts:** RUNNING = screen still changing at the end; STUCK = screen static ≥10 s (often a title screen waiting for input the harness can't give — *unknown*, not *broken*); CRASH = address/illegal/privilege exception followed by a static screen; HALT = double bus fault (definitely broken).

**Variants:** `cur` = today's code; `pre` = all three fixes switched off (pre-session behaviour); `notrace` / `oldvid` / `oldfdc` = one fix switched off each (trace emulation, video-address-counter model, WD1772 INTRQ-on-command).

## What was actually wrong (root causes found with the harness)

1. **WD1772 INTRQ not cleared on command load.** Loaders that poll the FDC interrupt line (MFP GPIP5) and never read the status register between commands saw the *previous* command's interrupt still pending, assumed the new one had finished, and issued the next command while the controller was busy (ignored). Xenon 2 lost sector 1 of every track after a seek, so its decrypted game was full of holes and it jumped into garbage (3/4 bombs). Fix: one line in `fdc_command()`.
2. **Trace emulation compiled out of the vendored Musashi** (upstream default). The 68000 T bit was ignored, so `ori #$A700,SR / jmp` launchers that rely on the trace exception fell straight through. Fix: `M68K_EMULATE_TRACE` on in the STBOX block of `m68kconf.h`.
3. **Video address counter** (`$FF8205/07/09`) advanced through the whole frame, borders included (80 KB by the bottom instead of 32 KB). Now follows the display-enable window. Just Buggin' took a privilege violation off the old values.
4. STE tier: TOS 2.06 boot hung on the microwire handshake (`tst.w $FF8922 / bne` waits for the data register to read 0 after the shift); modelled.

## Still broken in the box (pre-existing, all configs)

HALT (double bus fault): Chaos Strikes Back, Dark Side of the Spoon, Sensible Soccer; Rainbow Islands and Gauntlet II (illegal instruction in high RAM at $3F8xxx — the 4 MB screen area); Populous under TOS 1.04. Space Harrier halts as ST but runs as STE. These have exception reports in the harness output and are the next targets.

## Harness

`tools/stbox-harness/` in the tree: `build.sh <name> <stbox.c> [-D...]` builds a variant, `batch.sh <tos> <secs> <variants…>` runs the collection. Env knobs: `HARNESS_WATCH=lo:hi` (write watchpoint incl. FDC DMA), `HARNESS_PCHIST=N` (PC history at a fault), `HARNESS_DASM=a:b,…` (disassemble at the fault), `HARNESS_AT=ppc` (gate the dumps), `HARNESS_FDCMAP=1` (sector load map), `HARNESS_FDCCMDS=1` (FDC command trace, needs `-DSTBOX_FDC_TRACE`), `PISTORM_STBOX_DBG=1`, `HARNESS_STE=1` for batch.
